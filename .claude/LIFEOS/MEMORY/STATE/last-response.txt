Queue leak is fixed, and it was hiding a worse bug.

The pending queue is now a **set keyed by job** rather than an append log. `enqueue` refuses a duplicate and says so; `dequeue` removes on completion. New verb closes the loop:

```
conveyor complete <jobid> [vault/path.md]
```

It records the vault write, drops the queue entry, moves `review/ → done/`, and refuses to record a write it cannot actually see in the vault.

**The thing worth knowing:** wiring that up surfaced a real defect. Importing `dequeue` from the publisher ran the publisher's `main()` as a side effect, so *reading a helper triggered a live publish sweep*. A review gate firing from an import is the same class of failure as the regex bug yesterday. Now guarded by `import.meta.main`. I found it because the dropped-count printed `NaN` and I chased it instead of accepting the number.
